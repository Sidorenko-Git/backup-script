================================================================================
  ДОКУМЕНТАЦИЯ: ПЕРВИЧНАЯ НАСТРОЙКА RCLONE CONFIG ДЛЯ GOOGLE WORKSPACE SHARED DRIVES
================================================================================

1. ОПИСАНИЕ И ОСОБЕННОСТИ НАСТРОЙКИ
--------------------------------------------------------------------------------
Цель: Создать базвый remote (подключение) к Google Drive в headless-среде (Debian по SSH),
который будет использоваться как транспорт для монтирования всех Общих дисков (Shared Drives).

ВОЗНИКШИЕ СЛОЖНОСТИ И ИХ РЕШЕНИЯ:
1. Google Client ID:
   - Проблема: Стандартный shared client_id от rclone устаревает и вызывает предупреждения.
   - Решение: На этапе первичной настройки нажали Enter (пропустили), подтвердив использование
     shared client_id ('y'), чтобы быстрее завершить первичную настройку.

2. Отсутствие браузера на сервере (Headless mode):
   - Проблема: Сервер работает без GUI, встроенный веб-сервер rclone не может автоматически
     открыть браузер.
   - Решение: Выбрали 'n' на вопросе "Use web browser to automatically authenticate",
     выполнили сгенерированную команду `rclone authorize "drive" "..."` на ПК с браузером
     и вставили полученный JSON-токен обратно в терминал сервера.

3. Выбор Общего диска (Team Drive / Shared Drive):
   - Проблема: Если при выборе диска укажать конкретный номер из списка (например, 1 из 46),
     rclone привяжется ТОЛЬКО к этому одному диску.
   - Решение: На шаге `config_team_drive>` нажали Enter (оставили пустым). Это привязало 
     remote к корню учетной записи Google Workspace.

3. ПРОВЕРКА РЕЗУЛЬТАТА ПОСЛЕ НАСТРОЙКИ
--------------------------------------------------------------------------------
Для проверки корректности настройки выполните команду получения списка всех дисков:

  rclone backend drives gdrive_ws:

* Успешный результат: Команда вернет JSON-массив с именами и ID всех 46 Общих дисков.
